# 迁移与旧版兼容

## 继续使用旧版

无需操作。仓库沿原 Git 历史改名，保留所有旧标签和产物，不把 v2.8.3 替换成新助手。主分支保留 dist/destined-journey-summarizer.js，冻结为 v2.8.3，保护旧文件的 main、latest 和无版本外链。

旧仓库地址通过 GitHub 改名重定向继续可用。旧总结文件保持原版本内容，使用固定版本链接的用户无需随助手更新而升级。

## 升级个人预设

1. 备份个人预设和配置，保留聊天、世界书。
2. 当前脚本名称为“命定预设助手”，旧脚本可原地改名；名称不作为数据身份。仅将 [loader.js](../loader.js) 替换到原“【命定之诗】预设设置”内容中，保留 UUID 和变量。
3. 首次启动读取可访问的旧总结参数、提示词、Key 与启用状态，写入新命名空间及一次迁移标记。
4. 成功后停用旧独立总结入口，防止双重运行。已有新版设置优先，不清空旧数据；停用失败会阻止新助手启动并提示，可修复后重试。
5. 在统一面板检查参数和当前绑定，确认后再决定是否移除已停用旧入口。

优先识别旧 UUID 3eb6e3eb-7a14-47dc-900c-759cd2f0bf64。复制后更换 UUID 的脚本，仅在名称与旧加载内容匹配且候选唯一时迁移；多候选不猜测。需处于可访问的当前预设脚本树；放在其他范围或同时改名改 ID 的脚本需手动处理。

导入另一份预设可能替换个人脚本数据，无法保证跨预设自动寻找原有私有数据。需要保留个人设置时，优先仅替换原设置脚本内容。助手新装默认关闭总结。

## 后台档案升级

提示词迁移版本为 4。未修改的旧默认模板更新为原生条目列表，系统身份使用 system，规则和资料使用 user；默认启用时间地点档案。版本 3 的格式、检查与预填充选项迁移为对应条目，深度世界书和防合并选项移除。用户修改过的提示词内容、角色和顺序保留，旧动态来源条目转为可编辑的宏正文；发送时保证结果标签协议存在。旧世界书的纯文本正文不需要补标签；标签协议只作用于新的模型返回。

已有普通总结与大总结来源映射保留。首次读取旧记录时，为当前可用原文建立来源校验基线；这不能追溯识别升级之前已经发生的改楼。缺少来源的记录不会被当作可靠覆盖。后续编辑、删除和回复版本切换会使相关覆盖失效。

新增任务恢复、来源、独立总结书目录和受管全局绑定字段不进入配置分享。已绑旧书保留；仅凭名称相同不会自动接管其他世界书。

## 数据与回退

设置 UUID、聊天键、世界书名、总结条目名、大总结映射、自动隐藏记录保持兼容。关闭总结不删记录、不解绑、不发新请求。

v1 命名配置可以导入，解释为仅预设配置；不会重置总结。v2 分享文件不保证旧版能读，回退时使用升级前备份。

回退时停用新助手，恢复备份的设置脚本和旧总结加载器，再恢复旧启用状态，确保仅一个总结入口运行。旧脚本数据和世界书未删除，无需清空聊天；不要直接把升级后的新版配置库交给旧脚本解析。
