# 后台总结

总结把已经发生的剧情整理为世界书记录。默认可新建独立总结书，也可以明确选择酒馆已有的任意世界书作为保存位置。

## 页面分区

“总结”分为四页：**记录与任务**查看任务日志、控制楼层显隐和管理记录；**生成设置**调整自动批次、连接模型和正文提取；**提示词**只有普通总结、大总结两套预设；**世界书**管理绑定与迁移。保存反馈显示在助手左下角。

## 三种生成入口

- **自动总结**：打开总结页右上方的“自动总结”开关，达到设定阈值后后台处理。新安装默认关闭。
- **手动开始总结**：点击总结页顶部按钮，立即处理当前可总结的一轮，无须达到自动触发阈值；仍保留最近楼层，按单批上限拆分并选取完整回复。
- **指定楼层总结**：点击总结页顶部按钮，分别在两个数字框填写起始楼层与结束楼层，如 `12` 和 `19`，只总结选定范围；范围内须有可提取的 AI 正文，不能与有效总结重叠。

关闭自动总结时，手动和指定楼层仍可使用。大总结同时保留自动合并和手动选择连续普通总结后合并。任务运行期间，生成入口暂时禁用，完成或停止后恢复。

## 默认处理方式

- 默认使用自定义参数：累计 30 楼未总结消息触发、保留最近 10 楼、每批最多 20 楼，以完整 AI 回复结束。用户楼与 AI 楼都计数，包含第 0 楼开局。
- 用户输入保留全文；AI 默认提取 `tp`、`gametxt`，去除 HTML 注释，排除标签默认为空。材料附原始楼层编号；用户意图与实际剧情分别标记。第 0 楼有正文标签时正常提取；没有标签时不作为剧情材料发送，但会随包含它的首批成功归档隐藏，改写开局也会使原档案失效。
- 累计 15 条有效普通总结，将最早连续的 10 条合成大总结，保留其余普通总结。“生成设置 → 自动与批次”中的“普通总结累计”和“合并最早连续”均可修改，合并条数须小于触发条数。旧大总结分段保留，不反复滚动压缩；长期使用时记忆注入体积会逐渐增长。
- 普通总结深度 9998，大总结深度 9999。大总结启用后，来源普通条目保留并停用。配套预设的消息分区中，较早的大总结和随后普通总结进入 `VOID_memory`；未总结聊天和最新输入留在 `historical_record`。
- 只有世界书写入及读回校验通过后，才同步原生楼层隐藏。覆盖依据实际来源，不会跨过中间漏段或把不连续大总结之间的空白当作已总结。

## 推荐方案与批次

“生成设置 → 自动与批次”提供三种手选方案，不读取或修改预设的摘要开关：

| 方案 | 触发楼层数 | 保留楼层数 |
| --- | --- | --- |
| 已开启摘要 | 50 | 10 |
| 未开启摘要 | 20 | 5 |
| 自定义 | 自行填写 | 自行填写 |

选择推荐方案只填写触发数与保留数，每批上限独立保留；修改前两项会转为自定义。每批最多楼层是单次请求的材料上限，用于控制材料量，不是固定 Tokens 上限。同样的楼层数可能包含不同长度的正文。

达到触发阈值后，先确定本轮全部可总结范围，再拆分请求；同一轮中不重复判断触发阈值。例如 50 楼触发、保留 10 楼，本轮可处理 40 楼：每批 20 时为 20＋20，每批 30 时为 30＋10。实际范围以完整 AI 回复收尾；零散缺口、手动排除范围和末尾用户楼可能使批次略短。指定楼层也遵守单批上限，重生成已有记录保持原记录的完整范围。

默认串行：每批生成、校验、保存后继续下一批，下一批可以参考此前刚保存的记忆。勾选“并发生成批次”后可设置 1—8 的并发数；每组最多同时生成该数量的批次，再按楼层顺序保存，完成后开始下一组。同组批次只参考生成前已有的记忆，不包含彼此刚生成的结果。

某一批失败时保留同组已成功的结果，暂不启动下一组。任务区列出每批状态，可选择待处理批次，编辑保存、重新生成或跳过。“继续未完成批次”跳过已成功的批次，只恢复剩余工作；保存失败复用有效正文，显隐失败只补做显隐。待处理信息可在重新载入后恢复。自动大总结在普通总结整轮结束后检查。

## 正文标签

提取标签与排除标签都逐项添加：输入标签名称后按回车或点“添加”，点击标签旁的叉移除。无需输入逗号或尖括号；标点不会存入名称，粘贴含中文逗号、分号或空格的名称列表会自动拆分并去重。尚未添加的输入不进入设置。

排除标签默认为空；需要时仅移除已提取 AI 正文内部的对应标签及其内容，支持带属性和同名嵌套。用户输入保持全文。旧配置中单独的默认 `think` 会一次性迁移为空，其他自定义排除项保留；之后主动添加的 `think` 也会正常保存。旧大总结默认 8/6 同步迁移为 15/10，其他自定义数值保留。

## 楼层显示与隐藏

“记录与任务”前部显示全部、显示中、已隐藏的楼层数，分别统计用户输入与 AI 输出；显示与隐藏范围、每段楼层的类型和状态均可展开查看。可以按数字范围与消息类型显隐，也可以逐段查看或切换。

楼层明细默认折叠，展开后每页最多 30 楼；相邻且类型、状态相同的楼层可合并成一行。支持上一页、下一页、输入楼层编号前往，以及按消息类型和显隐状态组合筛选。只在点击“查看”时读取该段原文。收起明细会释放表格行，翻页不重复读取全聊天正文；刷新统计仍需扫描全聊天，以核对覆盖与显隐状态。

显示与隐藏范围各预览最多 6 段，零散范围再多也不会铺满页面；概览中的“查看”进入对应状态的楼层分页。筛选与翻页不修改总结参数，查看原文不重新刷新已打开的助手面板。

“按总结自动隐藏”是本聊天独立保存的开关。开启后按有效总结隐藏楼层，后续总结保存成功后继续处理；没有总结时显示“已开启，等待总结”，空聊天也能保存开启状态。关闭开关只暂停后续自动隐藏，保留当前楼层状态。

“隐藏范围”“显示范围”“隐藏已总结楼层”排列在同一行，都是立即执行一次的操作；“隐藏已总结楼层”处理全部有效总结覆盖的楼层。“显示全部楼层”立即显示所有消息。这些操作和逐段显隐都会暂停本聊天的自动隐藏，按钮不显示持续选中状态。刷新和重开面板保留开关状态，不重复执行手动操作。

重新开启开关会清除本面板的全部手动选择：已总结的楼层隐藏，本面板曾手动隐藏但未总结的楼层恢复显示；没有总结也照常恢复。酒馆原有或其他工具管理的手动隐藏不在清除范围内。任务运行期间按钮与开关暂时禁用，仍可查看楼层。总结失效、删除或解绑时，助手仍会恢复自己自动隐藏且已失去有效覆盖的原文，避免原文和记忆同时缺失。

## 任务提示与恢复

任务以带时间的日志显示准备材料、请求生成、提取与校验、保存记录、同步楼层和完成。成功后不在任务区重复展示总结正文；正文从普通或大总结记录查看。仅待处理任务提供结果编辑和重试入口。酒馆顶部提示不带遮罩，也不主动移动焦点或聊天滚动位置。“查看”才会打开任务详情。

“清除日志”移除本次日志。已完成任务会收起任务区；运行中或待处理任务保留正文与重试入口，后续阶段继续记录。此操作不删除世界书中的总结记录。

关闭顶部提示只是收起提示；关闭助手面板也不会停止任务。同一任务的进度不会反复弹出。成功提示约 4 秒后收起；若已关闭进度提示，成功只更新面板状态。失败可以再提示一次，关闭后仍保留待处理入口。

“暂停自动总结”允许已开始的一批或一组完成，停止启动后续批次。“停止本次任务”取消本轮全部正在进行的总结请求，生成及重试等待时可用；提交保存期间暂不可用。停止的批次等待手动继续，不会立刻自动重启。单次请求等待上限 5 分钟，自动重试最多一次。

| 待处理原因 | 默认恢复动作 |
| --- | --- |
| 请求失败或返回格式不合格 | 重试生成，读取最新参数并重新核对来源 |
| 已有有效正文，但保存失败 | 重试保存，复用正文 |
| 总结已保存，显隐同步失败 | 重试显隐，不再调用模型 |
| 来源楼层、回复版本或原总结改变 | 重新生成，不能直接提交旧结果 |
| 主动停止 | 继续本次，或跳过该批次 |

详情中可查看原始返回、技术原因、复制内容，或编辑待保存正文。手动编辑框只填写最终正文，无须添加结果标签。“跳过此批”保留原文并排除该批次的自动处理。删除或手动停用记录也不会立即触发自动重建；回档大总结后，相关范围不会马上再次自动合并。

切换聊天、预设或卸载时取消旧任务，恢复记录归属原上下文，迟到结果不串写。改楼、删楼、回复版本变化会使对应记忆失效，并仅恢复助手自己隐藏且已失去有效覆盖的原文。用户原先手动隐藏的楼层不会被自动打开。

## 任务期间的操作

生成入口、记录修改／启停／删除／回档、绑定迁移、批量显隐，以及整体配置应用／恢复／重置暂时禁用。界面同时显示文字原因；执行入口也会拒绝重复写入。

页面浏览、记录查看／复制、请求预览和导出保持可用。提示词和连接参数仍可编辑，标注为“下次任务生效”；当前任务使用固定材料与参数。其他助手页面和悬浮入口保留“总结中／待处理”标记，总结状态与预设保存状态独立。

## 提示词与输出协议

普通总结与大总结各有 12 个默认条目，其中 7 个默认启用。两套预设独立编辑，右侧开关启停，拖动手柄排序，点击名称弹出编辑窗口修改名称、角色和内容，也可删除。手柄支持 Alt 加上下方向键排序。

| 默认发送顺序 | 角色 | 内容 |
| --- | --- | --- |
| 1 | system | 第三方剧情档案员身份 |
| 2 | user | 创作与总结规则 |
| 3 | user | 时间地点档案；可切换分项档案或自定义正文 |
| 4 | user | 世界书前置、用户设定、角色描述与性格、场景、世界书后置，合并为一个条目 |
| 5 | user | 此前有效的大总结与普通总结，仅作参考 |
| 6 | user | 本次原始楼层，或选中的连续普通总结 |
| 7 | user / assistant | 尾部指令与 AI 预填充二选一，默认使用 user 尾部指令 |

“简短检查”和“归档复核”是默认关闭的可选条目。格式条目互斥，检查条目互斥，尾部两项保持二选一；它们都能直接编辑。条目删除与顺序修改会保留，不会自动补回默认列表。

支持提示词专用导入导出、自定义变量、编辑窗口内插入变量和展开请求预览。预览不会发送请求，未达到批次条件时展示材料占位说明。常用宏为 `{{summary.history}}`、`{{summary.material}}`、`{{summary.start}}`、`{{summary.end}}`、`{{user}}` 和 `{{char}}`；自定义宏允许相互引用，循环引用会报错。`{{summary.output_format}}` 为旧模板兼容保留。

总结按条目中的自然 role、顺序和展开内容直接发送给 generateRaw，不添加防合并标记，也不在发送末尾恢复或重写请求。配套预设的「消息处理」脚本只认领正文边界，总结请求不包含这些边界，因而保持原样。更新时需同步使用该预设脚本，并停用旧全局 SP 合并器后刷新酒馆。酒馆连接选择的后处理保持生效，部分模型接口还会合并连续同角色消息；首部规则和末尾 assistant 预填充遵循接口自身的转换规则。

Vertex／Gemini 还会经过酒馆后端的 [Google 格式转换](https://github.com/SillyTavern/SillyTavern/blob/release/src/prompt-converters.js)：开头的 system 进入系统指令，中间及末尾的 system 转为 user，连续 user 合并，assistant 转为 model。关闭可选后处理也不关闭这一步。因此默认条目可在后台表现为一份系统指令与一条包含全部材料的 user；开启 assistant 预填充时另有一条 model。非预填充尾部即使改成 system，也会并入相邻 user。OpenAI 兼容接口在后处理关闭时可保留连续 user 条目；区别来自接口协议，而非主连接／自定义连接开关本身。

“生成设置 → 自动与批次”保留用户前缀和 AI 前缀，方便配合自定义总结预设。用户前缀默认 `{{user}}`，展开为当前用户名；AI 前缀默认 `AI`。两者均可修改并使用名称宏，旧配置中的自定义值继续保留。每楼还会附带固定的“用户输入／AI 正文”标签。

此前记忆只供理解连续性，重生成旧记录时不读取其后的记忆。不读取深度世界书；自身总结统一通过记忆宏提供，避免重复。材料中的角色指令和台词按资料处理，不应当作档案员的操作指令。

检查条目只改变发给模型的提示文字，不切换模型本身的推理功能。尾部预填充作为 assistant 消息发送。所有新生成结果必须包含且只包含一组：

```xml
<summary_result>
最终总结正文
</summary_result>
```

标签外的解释、思考或其他输出不会保存。缺失、空白、重复、嵌套、未闭合标签进入待处理；实际发送的预填充起始标签参与解析。旧记录的纯文本正文保持不变。

默认正文为**时间地点档案**：用 `---` 分隔日期与地点段，下一行是 `日期 | 地点:`，随后缩进书写时间和连贯事件；有明确内容时补充【信息变动】【关系变动】【战斗记录】【未决事项】。未知日期、时间、地点写未明，不编造。普通总结保留关键事实和因果，大总结按原时间线去重整合。

**分项档案**固定以【时空与事件】开始，按需补充【信息与关系变化】【约定与未决事项】；**自定义正文**遵循用户编辑的正文规则。启用未经编辑的默认格式条目时，发送要求与正文结构校验对应；编辑格式内容后视为用户自定义结构，只保留共享的结果标签校验。点击格式条目即可查看和修改完整规则。

## 连接与世界书

酒馆主连接和自定义 API 都支持温度与最大 Tokens 的跟随／指定数值。自定义模式可获取模型列表或手动填写；刷新列表保留已有选择。两种模式均不提供测试连接按钮。后台请求不切换 RP 主连接。

首次总结前未绑定世界书时，自动创建并绑定本聊天的独立总结书；页面显示此行为。

“本聊天的总结世界书”提供查看记忆、条目编辑、迁移、解绑和删除。下拉框列出酒馆全部世界书，可刷新列表或输入新名称创建。绑定更换后续保存位置；迁移同时搬移现有总结。删除后立即刷新选项；已从酒馆删除的书会解除失效绑定并恢复助手自己隐藏的原文，等待用户重新绑定。助手只移除自己实际加入全局的书；不会根据名字、深度或其他书的位置猜测用途。

删除总结书需要确认；若含有其他条目，只清理总结条目。主动解绑／删除后暂停自动建书，直到重新绑定。绑定同一本总结书的聊天会共享对该书的修改。

API Key 按接口地址独立保存。命名配置、恢复点和导出采用白名单，不包含密钥、聊天、任务内容、世界书正文、来源记录或绑定管理信息。

## 真实酒馆实测清单

自动回归使用模拟宿主，不发送真实模型请求。跨工作区检查加载配套预设的实际消息处理脚本，验证正文与并发总结互不混淆；真实环境验收由使用者完成。建议记录 SillyTavern、酒馆助手、预设版本和所用 API 模式。

1. 启用总结后连续 RP，确认总结请求与 RP 请求可同时进行，顶部提示的出现、更新和关闭不影响输入或滚动。
2. 任务中切换助手页面、关闭／重开面板，确认状态与草稿保留；关闭提示后任务继续，停止只影响本次总结。
3. 检查保存正文只有结果标签内内容，原生隐藏仅覆盖已可靠保存的来源楼层；模拟连接失败后可从待处理入口重试。
4. 切换聊天或回复版本，确认迟到结果不串写；多本全局书并存时，仅助手管理的绑定变化。
5. 切换预设并切回，检查消息脚本在离开时卸载，返回后只保留一个实例。首次升级后刷新酒馆，确保旧 SP 已停止运行。
6. 检查主连接与自定义 API 的模型及参数实际生效，并核对 RP 最终请求中 `VOID_memory` 与 `historical_record` 的顺序。

自动验证范围和消息处理检查命令见 [验证说明](VERIFICATION.md)。
